# IOC Log Enricher

IOC Log Enricher is a small SOC-focused Python CLI tool for extracting public IPv4 indicators from log files, analyzing local event context, enriching indicators with AbuseIPDB, and generating analyst-friendly reports.

The project was built as a learning and portfolio case for Junior SOC Analyst skills: log parsing, IOC extraction, public/private IP filtering, contextual triage, external reputation enrichment, evidence collection, and CSV reporting.

## What the tool does

- Extracts IPv4 addresses from a log file
- Validates IP addresses with Python `ipaddress`
- Filters out private, local, loopback, reserved and non-global IP addresses
- Counts occurrences of each public IP
- Collects evidence:
  - line numbers
  - sample log line
  - local event context
- Assigns a basic analyst verdict:
  - `HIGH`
  - `SUSPICIOUS`
  - `CHECK`
  - `INFO`
- Optionally enriches public IPs via AbuseIPDB
- Prints a readable console report
- Exports results to CSV for further analysis

## Why this project exists

This project demonstrates a basic SOC analyst workflow:

1. Read raw logs
2. Extract possible indicators of compromise
3. Remove irrelevant internal/local addresses
4. Check local log context
5. Add external reputation data
6. Produce a report that can be reviewed, shared, or imported into another tool

It is not meant to replace a SIEM or threat intelligence platform. It is a practical Python mini-tool that shows how IOC triage logic can be built step by step.

## Installation

Clone the repository:

```bash
git clone https://github.com/prodlovely88-ux/ioc-log-enricher.git
cd ioc-log-enricher
```

Create and activate a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Environment configuration

The tool can work in two modes:

1. Local-only mode without AbuseIPDB
2. Enriched mode with AbuseIPDB reputation data

To enable AbuseIPDB enrichment, create a `.env` file:

```bash
cp .env.example .env
```

Then add your API key:

```env
ABUSEIPDB_API_KEY=your_api_key_here
ABUSEIPDB_MAX_AGE_DAYS=90
```

If `ABUSEIPDB_API_KEY` is not configured, the script still works and marks enrichment source as:

```text
local_only
```

Security note:

```text
.env must never be committed to GitHub.
```

The `.gitignore` file should contain:

```gitignore
.venv/
__pycache__/
*.pyc
.env
reports/*.csv
```

## Verdict logic

The tool uses local log context to assign a basic analyst verdict.

### HIGH

Used when an IP appears multiple times in clearly suspicious authentication-related events.

Example context:

```text
Failed password
invalid user
authentication failure
```

Typical meaning:

```text
Repeated suspicious login activity from the same public IP.
```

### SUSPICIOUS

Used when suspicious context is found, but the activity is less repetitive or has weaker local evidence.

Example:

```text
One or two failed SSH login attempts from a public IP.
```

Typical meaning:

```text
Potentially malicious activity that should be reviewed.
```

### CHECK

Used when the context is weak, ambiguous, or requires manual review.

Example:

```text
GET /login from 8.8.8.8 status 200
```

Typical meaning:

```text
The IP is not automatically malicious, but the surrounding event deserves attention.
```

### INFO

Used when a public IP is found but no suspicious local context is detected.

Typical meaning:

```text
Public IP observed, no immediate suspicious context.
```

## AbuseIPDB enrichment

When AbuseIPDB is configured, the tool adds external reputation fields to each public IP.

Example fields:

```text
abuse_confidence_score
abuse_total_reports
abuse_country
abuse_usage_type
abuse_isp
abuse_domain
enrichment_source
```

Important analyst note:

A score of `0` is not the same as missing data.

Example:

```text
8.8.8.8
AbuseIPDB score=0
```

This means AbuseIPDB returned reputation data and the abuse confidence score is zero. The analyst should still consider local log context before making a final decision.

## CSV report

The tool saves the CSV report to the path provided with `-o`.

Example:

```bash
python src/extractor.py logs/sample.log -o reports/ip_report.csv
```

CSV fields:

```text
ip,count,verdict,reason,line_numbers,sample_line,abuse_confidence_score,abuse_total_reports,abuse_country,abuse_usage_type,abuse_isp,abuse_domain,enrichment_source
```

CSV output can be used for:

- manual investigation
- spreadsheet review
- reporting
- SIEM-like workflow
- portfolio evidence
- future enrichment or automation

```text

185.220.101.1  -> SUSPICIOUS
8.8.8.8        -> CHECK
```

Interpretation:

- `45.155.205.233` had repeated failed login activity and was classified as `HIGH`.
- `185.220.101.1` had suspicious login-related context and strong AbuseIPDB reputation data.
- `8.8.8.8` had weak local context and AbuseIPDB score `0`, so it was marked as `CHECK`, not as malicious.

## Limitations

This tool is intentionally simple.

Current limitations:

- IPv4 only
- No IPv6 support yet
- No JSON log parsing yet
- No automatic severity scoring model
- No bulk directory scan mode yet
- No VirusTotal enrichment yet
- No ASN-focused enrichment yet
- No timeline correlation yet

These limitations are acceptable for the current project stage because the goal is to demonstrate clear SOC thinking and practical automation basics.
